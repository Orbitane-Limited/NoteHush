# Cold-launch checkpoint diagnostics

The post-merge main run [40018520354](https://github.com/Orbitane-Limited/NoteHush/actions/runs/40018520354) failed in the host-only cold-launch harness with `checkpointNotObserved`. The original error did not identify which lifecycle checkpoint timed out or whether a recovery snapshot had been written. The UI test suite did not start in that run.

The same test app binary, whose app/config/project tree matches merged main `2f3b359`, passed the existing harness three consecutive times locally before the instrumentation change and once after it. These runs used only generated UUID fixtures and sent no UI input. They are comparative evidence, not proof that the hosted failure is harmless or resolved.

The harness now labels each fixed checkpoint phase and, on timeout only, reports whether the test app is active/terminated, whether its isolated recovery file exists and is readable, the snapshot revision and tab count, the selected-tab index, and whether the unchanged acceptance predicate matched. It emits no text, paths, UUIDs or bookmarks. All original 10-second deadlines and data, selection, file-byte, quit and viewport assertions remain unchanged.

Strict Swift formatting, diff checks, harness compilation and four local harness runs passed against a freshly built test app whose app/config/project tree matches main `2f3b359`. They used generated UUID fixtures and sent no UI input. Exact-head hosted CI passed on commit `31e111c735a312ef37bb41dea9f45358d39ce09d` in [run 40020535945](https://github.com/Orbitane-Limited/NoteHush/actions/runs/40020535945). The diagnostic did not trigger in that run.

The next exact-head check, [run 40022507807](https://github.com/Orbitane-Limited/NoteHush/actions/runs/40022507807), reproduced the timeout at `middleViewportRestoration`. At timeout the app was active, the recovery snapshot was readable at revision 11 with two tabs, and the selected tab was index 0; the complete unchanged viewport predicate was false. The UI test suite did not start. This narrows the failure to state observed during middle-viewport restoration, but the first diagnostic did not reveal which component differed. A follow-up now records only comparison booleans for tab order/content and persisted workspace fields, plus the generated fixture's logical scroll line and numeric offset. Text, paths, IDs, bookmarks and selection contents are never logged. No assertion, checkpoint deadline or retry policy changed.

Full exact-head CI on the refined diagnostic commit `1330d39d` passed in [run 40024457184](https://github.com/Orbitane-Limited/NoteHush/actions/runs/40024457184); the timeout did not recur, so no field-level diagnosis was produced. The original intermittent viewport failure remains unresolved. The successful rerun is recorded separately and is not treated as a replacement for the failed run.
