# Incremental chunk input surface prototype

Issue #75 remains unresolved. This generated-data prototype combines a custom
`NSTextContentManager`, an AppKit `NSView` implementing `NSTextInputClient`, a
piece-based edit model, and direct TextKit range layout. It is an isolated
experiment; no application source or supported-file behavior changed.

## Result

The fixture is exactly 10,485,760 UTF-8 bytes: `123456789012345\n` followed by
repeated `خط📝`. It was created in memory and no user file was read. The prototype
verified exact string equality for generated insertion, repeated synthetic
typing, marked-text setting and commit, middle insertion, append at end,
cross-chunk replacement, a first-chunk TextKit replacement, and an empty draft.
The model edit transaction itself measured 0.069 ms.

| Observation | Result |
| --- | ---: |
| Initial 10 MiB chunked surface construction | 2,507.9 ms |
| First synthetic window-dispatched key event | 30.61 ms |
| 20 repeated synthetic key events, median / p95 | 28.71 / 28.98 ms |
| Marked-text set / direct commit | 28.64 / 28.80 ms |
| Middle insertion | 25.95 ms |
| Background Core Text line index | 1,700.6 ms |
| Main-actor 16 ms heartbeat ticks during indexing | 72 |
| Indexed lines / custom text elements | 57,029 / 1,296 |

The custom surface requested TextKit ranges at the beginning, middle and end,
and its generated bitmap captures contained rendered glyphs at all three
positions. The recorded requested/covered UTF-16 intervals were `0–20,184`,
`2,579,588–2,598,760`, and `5,225,783–5,242,910`. The line index used for those
requests was generated by Core Text; this run did not compare the full index
against native TextKit geometry for arbitrary Unicode or establish an attached,
physically visible scroll result.

## Limits and conclusion

Key events were synthesized in-process and dispatched to a generated AppKit
window. Marked text was set through the client methods directly; this did not
exercise a physical keyboard, a real input method, or Japanese composition.
The probe has no production selection navigation, undo integration, accessibility,
Find, print, tabs, file access, recovery, or restart behavior. It does not test
external file conflicts or sandbox behavior. Bitmap captures are diagnostic,
not a frame-presentation measurement.

The measured dispatch is above the PRD's 16.7 ms typing target, and the initial
line-index construction exceeds the one-second open target. The line-aligned
custom surface therefore does not provide a product correction. The exact
source, compiler command, and generated-only process output are retained here
for reproducibility; issue #75 remains open.
