# Recovery storage validation — 2026-09-06

Issue #4, storage foundation only. Xcode 26.6 / Swift 6.3.3 on Apple silicon.

The first integration run exposed Foundation's alternative missing-file error (`fileNoSuchFile`, not just `fileReadNoSuchFile`). The implementation now recognizes only genuine Cocoa/POSIX missing-file codes as absence; permission and other I/O failures remain errors. Assertions were retained and the implementation corrected.

The core suite covers:

- Fresh store versus corrupt or unreadable store.
- Multiple tabs, selected tab, exact Unicode/CRLF bytes and UTF-16 selection.
- Checksums, truncation, previous-generation fallback and preservation of damaged evidence.
- Unknown schema in either slot blocking reads/writes, and conflicting same-revision generations.
- Primary/backup publication failure, retry and unchanged committed revision.
- Stale work, byte-distinct canonically equivalent strings, thirty competing tasks and independent store instances.
- Held disk lock, private file permissions and invalid snapshot rejection.

This does not establish app-level quit/relaunch behavior, power-loss durability, minimum-OS/Intel runtime compatibility, IME behavior or performance budgets. Those gates remain in issues #5 and #11–#13. The full-snapshot format is an interim correctness implementation; per-tab persistence and size/performance validation remain required before v1.0.0.

Executed command/results and the exact GitHub run link are recorded on the issue #4 PR. No user documents were used: tests create and remove unique temporary fixtures.
