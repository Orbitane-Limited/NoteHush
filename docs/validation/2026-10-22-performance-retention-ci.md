Date: 2026-10-22 UTC. Issue #57 / PR #60. Follow-up to the [retention implementation](2026-09-08-performance-retention.md).

With renewed exclusive-input availability, sufficient disk headroom and the owner's Automation Mode setup, run [39862075645](https://github.com/Orbitane-Limited/NoteHush/actions/runs/39862075645) reached the runner at head `068107e2daba0c637f4a01f1184f478c4246cd86`. Repository validation stopped after 51 tests in 161.102 seconds: two interaction-driver subcases exceeded their existing ten-second subprocess limit. App builds, crash drills and UI tests did **not** execute. Artifact upload independently failed with GitHub's organization storage-quota error. Both failures remain failures; the run is not accepted CI evidence.

The command doubles previously created five new Python executables per scenario and started an interpreter for each fake command. They now use one immutable shell dispatcher for the test class, reached through scenario-local command links. Each scenario still has independent files, environment, stage journal and injected failure. Real shell-driver control flow, all assertions, success/failure stages, statuses and the ten-second limit remain unchanged. Child environments contain only the needed host fields and test controls.

A first shell-stub revision still timed out in its successful-launch case inside the restricted command environment (51 tests, 90.720 seconds, one error). An additional bounded shell trace in the runner's normal execution environment completed all 13 expected stages, including exactly one cleanup, in 2.571 seconds. These observations do not establish a single cause for the earlier timing failures. After sharing the immutable dispatcher, all **51 repository tests passed in 2.451 seconds** in the normal execution environment. Configuration/link validation, shell syntax and whitespace checks passed. No timeout was increased and no failed observation was discarded.
