# Testing Strategy

Tests protect user data and measure behavior. Passing a build is not proof of data recovery, performance, accessibility or App Store readiness. Record executed commands, toolchain, commit and hardware with results.

Required CI runs on GitHub-hosted `macos-26` after the repository became public. GitHub documents standard hosted runners as free for public repositories. A prior self-hosted run used 9m52s for validation and 11m27s for its 137 MB verification upload, exceeding the former 20-minute job budget despite successful tests. This transfer allowance does not change Xcode's 30-second default/60-second maximum test-case limits or any assertions.

Native validation requires the [runner disk-headroom preflight](docs/SELF_HOSTED_RUNNER.md#disk-headroom-and-retained-evidence): at least 20 GiB or 10% of each workspace/temporary filesystem, whichever is larger. It fails before native work and retains a fresh capacity report per invocation. Repository tests cover both threshold boundaries, larger volumes, invalid/unreadable capacity, either volume failing, report retention/failure and all seven shell entry points stopping before native commands. These tests use injected capacities and command stubs; never fill the user's disk to test the gate. See the [confirmed cache-reclamation kills](docs/validation/2026-09-07-runner-storage.md). Exact recovery, screenshot and time-limit assertions remain unchanged.

## Layers

| Layer | Required coverage | Where |
| --- | --- | --- |
| Unit | Unicode/range validation, text formats, model invariants, revisions | Core XCTest suite |
| Persistence integration | atomic checkpoints, stale writes, corruption, fallback, unknown schema, denied writes, migration, repeated loads | temporary-directory core tests |
| File integration | encoding round trips, mixed newlines, conflicts, failed saves, bookmark relink, file coordination | app integration target and sandbox fixtures |
| UI | tabs, editing, independent undo, clean quit/relaunch, close-window/relaunch, find, fonts, keyboard and file panels | isolated XCUITest workspace |
| Crash drill | SIGKILL during write and continuous input, last acknowledged checkpoint restoration | child-process harness + manual signed build |
| Performance | startup, restore, typing, tab switch, memory, energy, large files | optimized build + Instruments/signposts |
| Distribution | sandbox access, signing, privacy resources, universal binary, archive validation | CI artifact inspection + TestFlight |

## Unattended UI prerequisite

Unattended XCTest entry points additionally require `python3 scripts/check_ui_automation.py`. This read-only preflight checks Apple's Automation Mode status before preparation and again after building. Disabled mode requiring administrator authentication, unreadable status or unexpected output fails before test execution. It never changes authorization, inspects system dialogs or substitutes for exclusive input/accessibility. Six offline regressions cover every known status combination, malformed/partial output, command failures, the exact bounded status-only invocation and all three shell drivers stopping before native work. See [runner authorization](docs/SELF_HOSTED_RUNNER.md#ui-automation-authorization).

## Critical scenarios

1. Create three untitled tabs including emoji, combining marks and Urdu. Edit a named file. Select the middle tab, select text, scroll, resize, quit immediately after typing. Relaunch: content/order/selection/scroll/frame restored, source file unchanged, no save prompt.
2. Close via red window button and repeat. Close an individual unsaved tab and reopen it. Test bounded recently-closed history and explicit clearing.
3. Kill a helper process before/during/after an atomic checkpoint. Restore the last committed version; never accept half a workspace. Measure actual possible lost-input interval.
4. Truncate primary, corrupt checksum, remove a referenced blob, duplicate tab IDs, use an unknown schema. Verify fallback or read-only warning and preservation of original evidence.
5. Inject write, rename and permission errors (do not fill the user's actual disk). Verify nonmodal warning, preserved dirty state, retry, explicit export, and no false success.
6. Rename/delete/revoke access to a source file. Externally modify it after open. Save must not overwrite without conflict handling; Save As keeps text.
7. Round-trip UTF-8/BOM, UTF-16 LE/BE, CRLF/LF/CR/mixed, trailing newlines, emoji and RTL. Reject malformed UTF-8, odd UTF-16, binary content and oversized files.
8. Type with Japanese/Chinese IME, Urdu RTL, dead keys and emoji; undo after tab switching. No marked-text truncation, cross-tab undo, smart-quote substitution or wrong selection offsets.

## Required checks by change

- Repository automation: `python3 -m unittest discover -s Tests/RepositoryAutomationTests -v` uses fake GitHub responses and temporary documentation fixtures. It verifies canonical transfer routing, full pagination, read-only preview, explicit local roadmap generation, idempotent creation, dependency links and preservation of edited issue bodies. Failed listings, ambiguous titles and malformed repository arguments must prevent mutations. CI runs these tests without GitHub API access; live verification uses the bootstrap's default read-only mode.
- Docs: relative-link validation and traceability review.
- Privacy metadata: configuration checks require the audited user-selected-file and app-container metadata reasons and no tracking/collection. Python regressions reject missing, duplicated or unaudited declarations; archive validation compares the bundled manifest with source. Recheck Apple's approved reasons when API usage changes.
- Store delivery: repository tests exercise exact main CI and environment gates, monotonically increasing build numbers across paginated responses, profile/identity/entitlement rejection, JWT signature conversion and credential cleanup with isolated fixtures. Apple's native requirement compiler checks the actual verifier argument, and the extraction helper reads the installed codesign tool's public certificate without modifying system code or using private signing credentials. Validate workflow syntax with actionlint. Follow [the signed-delivery protocol](docs/APP_STORE_DELIVERY.md); fixture tests and unsigned archives never qualify a real signed/TestFlight result.
- Store materials: compile the original icon with the app and verify all ten macOS PNG slots. Archive checks require its compiled icon and the audited encryption flag. Check metadata character/UTF-8-byte limits, website publisher/URL guards, real responsive browser layouts and public anonymous HTTPS access; previews are explicitly unpublished. The app icon renderer and isolated headless website checks use no Mac keyboard/mouse input. Dock/Finder appearance and final app screenshots still require their own runtime checks.
- Store delivery: reject missing or wrongly typed exported encryption metadata, changed icon metadata, and absent/empty/directory/symlink icon resources before signing-tool inspection. Inject storage failure before signing inputs and storage loss after archive/export; each must stop the next native stage without uploading. These fixture tests do not perform signing or upload.
- In-app privacy: use an isolated workspace to open Help → Privacy…, select/scroll its read-only text, reopen it without duplicate windows, and close with Cmd+W while preserving drafts. Inspect light/dark and minimum-size layouts, keyboard focus and VoiceOver reading. Quit with Privacy open must retain the existing workspace checkpoint behavior. The local explanation does not verify public policy/support links; those need anonymous HTTPS checks after publication.
- Core: `swift test`, Swift formatting, recovery integration tests.
- Store quarantine checks use real attributes on generated directories/files/packages, reject marked artifacts without removing the mark, preserve symlink boundaries and fail when inspection is unavailable. The native macOS signing/attribute tools must be accessible to the test process.
- App: core checks + unsigned Debug build and Release archive; relevant UI cases when target exists.
- Persistence/lifecycle: all recovery tests + clean quit/relaunch + kill drill; corruption/future-schema regression.
- Release: all layers; archive validation and real TestFlight installation. Runtime test macOS 14 and current stable macOS; Apple silicon and an Intel Mac if Intel is advertised. Cross-compilation alone is insufficient.

Run `bash scripts/check.sh` for formatting, configuration, core tests, 83 SIGKILL drills in each of Debug and Release, AppKit integration tests, sandboxed XCUITests, Debug build and universal Release archive verification. Logs and `.xcresult` bundles are written to `build/logs/`. GitHub retains the complete verification directory for seven days after a failed or cancelled CI/delivery run; successful runs retain the streamed job log without uploading the large result bundles. The unsigned archive is uploaded for seven days only for a successful run on `main`, not for each pull request. The explicit performance workflow retains its measurement result bundles for seven days on every outcome because raw measurements are required evidence. Failed/cancelled measurements also keep a private runner-side copy of logs and the generated fixture manifest, so the sandboxed recovery workspaces remain locatable if the checkout is later cleaned. CI attempts a runner-local fallback if the failure-log upload fails, but its GitHub-hosted VM is ephemeral; the upload failure remains a CI failure and the local copy is not durable. Self-hosted delivery and performance workflows use the private runner fallback. `bash scripts/test_app.sh` repeats the app tests; `python3 scripts/test_crash_recovery.py` repeats the crash drills; `bash scripts/archive.sh` repeats archive validation.

App tests require an awake, unlocked GUI login on the runner, exclusive keyboard/mouse use, and ad-hoc local signing. Native-panel tests wait for clickable controls before sending folder shortcuts and again for the Open button after Go to Folder navigation; a visible panel alone does not establish that its controls are ready. If the control does not become hittable within the existing bounded readiness check, retain its screenshot and fail the test instead of sending input early. After build-for-testing, the script re-signs only the test app with Config/NoteHush.entitlements, removing Xcode's injected filesystem exceptions. It requires exact entitlement equality before and after test-without-building; the separately running XCTest driver still uses Xcode's automation permissions. Earlier UI passes with Xcode-injected read access do not qualify the tighter sandbox. Ad-hoc signing disables hardened-runtime enforcement in Xcode; production signing/runtime validation remains a separate M6 gate. AppKit integration tests compile the same editor/window sources in a test bundle and inject unique temporary recovery directories. XCUITests use the `DebugUITesting` configuration (`pk.codehub.NoteHush.UITesting`), a separate sandbox identity from development and distribution builds. Its `NOTEHUSH_REQUIRE_TEST_WORKSPACE` compile condition rejects missing/invalid workspace IDs with exit status 78 before creating the app. Tests launch it with `NOTEHUSH_TEST_WORKSPACE=<UUID>` and use `Application Support/NoteHush/UITests/<UUID>` within its own sandbox. Release has no environment override. Fixtures are never reset into normal recovery storage and do not contain user notes.

Run the complete UI suite through `scripts/test_app.sh`: Xcode also sandboxes its UI runner, so the host script creates a disposable APFS image, runs the mounted-file scenario with the other tests, detaches the image, then runs the offline-restoration scenario against the same isolated workspace. Direct Xcode runs skip these two tests if no host fixture exists; the CI script requires both scenarios to actually pass, so a missing fixture cannot silently weaken CI. The fixture script only removes its generated UUID directory, detaches before deletion and cleans up on shell exit/interrupt. A per-checkout lock prevents overlapping fixture runs. If a terminated run leaves a fixture behind, confirm no test run is active, inspect it and use `python3 scripts/volume_fixture.py cleanup` before rerunning; never point the helper at an existing user volume.

The checkpoint scheduler uses an injected clock and gated writer to exercise a cancelled debounce, continuous typing, immediate shutdown, repeated shutdown and a final snapshot queued behind slow I/O. The child harness runs six publication timings and three continuous-input interruptions using the production checkpoint timer. Another 74 drills retain the original 28 manifest-publication cases and add immutable blob writes, real legacy migration, damaged-bundle preservation and reclamation. They pause real writes after temporary data, file synchronization, rename and directory synchronization, or pause removal after unlink and directory synchronization. They compare the entire restored workspace with an independent fixture oracle and verify exact external source bytes. Both Debug and Release must pass all 83 drills; early exit, a missing gate or normal termination cannot pass as SIGKILL. Storage fault tests also reject false success when a renamed checkpoint is retried while directory synchronization still fails. Blob regressions verify zero text reads/writes for metadata-only warm commits, one changed blob for a one-tab edit, fresh-load checksum verification, fingerprint invalidation, missing references, finite evidence retention/export, symlink/FIFO/path rejection, migration write failures and same-revision cleanup retry. AppKit capture tests cover metadata/attribute reuse, direct/batched storage replacement, exact Unicode, marked-text commit and explicitly grouped undo. Migration fixtures encode real inline-text schemas 1–5. These drills do not measure a worst-case 500 ms lost-input bound under every disk/OS condition. Tests use unique temporary roots; never make test flags capable of deleting normal user data or add sleeps to hide races.

File tests round-trip exact bytes across supported encodings, literal BOM characters, mixed newlines, emoji, RTL and long lines. They reject malformed encodings, binary controls, sparse oversized files, FIFOs and directories; exercise external changes/deletion, symlink/hard-link identity, cancelled reads and failed publication. Gated AppKit tests cover late cancelled results, dirty file recovery and typing during Save followed by undo back to saved bytes. UI tests exercise actual sandboxed Open/Save As panels, cancellation and a LaunchServices file request into an isolated running workspace. Injected bookmark tests cover stale refresh, balanced access, revoked authority, resolution/creation failures, legacy bindings, schema-2 migration and an external edit after overwrite approval. AppKit tests verify relink preserves the draft/baseline and Reload can undo back to the draft. Sandboxed UI tests cover moved files after restart, bookmark renewal after atomic Save, denied file permissions, delete/relink/Save As, conflict preview/reload/undo, repeated overwrite review, and Quit during a conflict. A disposable APFS disk image exercises mounted-volume Save and offline restoration without automatic mounting; it never targets an existing user volume. These locally signed tests do not replace production signing, physical removable-drive, TCC-specific Desktop/Documents, or compatibility release gates.

The two long relink/Save As and repeated-overwrite cases open their initial generated source through the existing public Finder/LaunchServices path. XCTest first launches the mandatory UUID workspace; setup validates the isolated bundle, app path and unchanged process ID, then waits for the selected file and exact initial text. The actual relink/conflict/Save As interactions remain native UI actions with every existing byte/content assertion and time allowance. Other file-access cases and the dedicated file-panel suite retain initial Open-panel coverage. This reduces repeated setup input and does not diagnose the unexplained event-delivery stalls in #29.

The file-panel helpers enter each generated path in the Go to Folder field's initial selection, then require the field's complete value to match before Return. A mismatch fails with a static message instead of logging the field's contents. The helpers do not click away that selection and send a redundant Select All event. Actual Open/Save As/Relink panels, keyboard path entry, source/destination checks and time allowances remain intact; the clipboard is untouched. Native validation and limitations are recorded in the [folder-input investigation](docs/validation/2026-09-07-native-folder-input.md).

The cold-launch harness keeps each checkpoint's original 10-second bound. On timeout, it reports a fixed scenario label, test-app active/termination state, recovery-file presence/readability, snapshot revision, tab count, selected-tab index and whether the checkpoint predicate matched. Viewport failures also report sanitized comparison booleans for revision, tab order/content, selection, file binding, closed tabs and preferences, plus the generated fixture's logical scroll line and numeric offset. The viewport fixture is already durably seeded before launch, so an exact no-op restoration may retain that revision; it still requires the full snapshot and viewport to match, and rejects any older revision. It never reports document text, paths, workspace identifiers or bookmarks. A timeout remains a failed lifecycle check; these fields are diagnostic evidence, not a relaxed acceptance oracle.

Search/navigation tests cover native Find options and replacement, undo isolation, logical line jumps, status updates, no matches and quit with the navigation sheet open. Core tests compare sparse Unicode indexing with an independent linear oracle, including partial UTF-16 selections, mixed endings and a 100,000-mark combining cluster. Gated AppKit tests reject stale/cancelled analyses and verify that caret movement does not rebuild the index. Find tests preserve and restore the macOS Find pasteboard without logging its prior contents; the general clipboard is untouched. Capture only the NoteHush window, never the whole application screenshot on macOS.

Issue #29 adds an opt-in [Undo diagnostic protocol](docs/validation/2026-09-07-undo-diagnostic.md). Only `DebugUITesting` compiles the probe, and both the exact isolated bundle/UUID and `NOTEHUSH_UNDO_DIAGNOSTICS=1` are required to activate it. Key observations distinguish Cmd+Z, next/previous tab and an undifferentiated other key, with repeat/workspace-target flags and an optional numeric event-source PID. A missing or zero source remains unknown; a PID does not establish human involvement. No typed characters or key codes are retained. It never records unexpected text, paths, bookmarks or clipboard data. A serial actor writes at most 256 observations into a fresh per-launch file in that UUID workspace. Normal Quit drains the diagnostic writer; forced termination can leave incomplete evidence. No other app/window/system-dialog diagnostics are obtained through this hook. The [input-source extension](docs/validation/2026-09-08-input-diagnostic.md) is headless preparation while native input attribution remains unresolved.

A valid trace or a passing focused case does not override failed CI, establish the prior failure's cause or certify performance. Existing functional timeouts and assertions remain unchanged; native diagnostic execution still requires the exclusive-input protocol above.

The sandboxed UI runner retains a warm LaunchServices request test. A separate, unsandboxed `ColdLaunchHarness` now verifies cold LaunchServices opening and restart against only the identified `DebugUITesting` app. It first verifies rejection of missing/invalid workspace IDs, then passes a fresh UUID through `NSWorkspace.OpenConfiguration.environment`. The app must publish its checkpoint in that UUID directory. Later cold launches preserve a dirty named buffer, untitled/closed drafts and preferences while an externally changed source remains byte-identical. Selection changes prove the file event ran, and increasing revisions prove each restart created a new checkpoint. Cleanup removes only the driver’s generated fixture directories. Never substitute a development/distribution build or a normal recovery path. A real signed Finder installation remains an M6 distribution check.

Settings control-order tests finish a font-size field edit while a popup selection awaits action delivery; both the size and Appearance/Zoom choice must survive the workspace callback. UI tests verify each menu choice immediately, preserving window-only diagnostics when a choice fails. Preferences tests cover schema-3 migration preserving the raw previous generation, bounded display values, zoom stops, all-tab/relaunch inheritance, exact UTF-16 file bytes, bindings and undo preservation, marked-text composition, unavailable fonts, and unwrapped horizontal scroll restoration. Native UI tests exercise font family/face/size, appearance, spelling, wrapping, zoom/reset shortcuts, Cmd+, and keyboard font selection, plus quitting while Settings has an uncommitted size field or native Print/Page Setup is open. Tab-management tests cover schema-4 migration, history validation, clearing/eviction after primary publication, coalesced close/clear, failed primary and failed cleanup writes, and same-revision retry. AppKit cases close more than 20 tabs, reopen and clear across restarts, preserve file baselines/Unicode/selection/scroll, protect duplicate open files and edits during accepted Save, and inspect tab radio roles, labels, close names, selected/dirty state, named controls, and visible selected tabs with 100 tabs at the minimum width. ## Performance protocol

Issue #56 adds the [settled CPU/RSS/physical-footprint protocol](docs/validation/2026-09-08-idle-resource-protocol.md). Its Swift host and strict offline parser are covered by normal compilation/repository tests. `NOTEHUSH_EXCLUSIVE_INPUT=1 bash scripts/measure_idle_resources.sh` is an operator-run native measurement after exclusive-input conditions are established; it is not run by ordinary CI. Both generated workloads, all 61 samples per window, exact recovery and normal termination are required. Failed recordings/fixtures remain retained, and Mach ticks are converted with the recorded timebase. A summary does not establish energy or release acceptance.

Use PRD budgets, Release optimization, no debugger. Record hardware, OS, power state, file sizes, character distributions and cache conditions. Run >=20 repetitions and report median/p95. Use a mix of 1 KiB, 1 MiB, 10 MiB and 100 MiB files, a long unbroken line, 100+ tabs, RTL, CRLF and Unicode. Distinguish process launch from first editable frame. Use Instruments Time Profiler, Allocations and Energy; verify no serialization on the main thread. Flaky shared-runner wall-time tests are informational; reproducible reference-hardware regressions gate release.

`swift run -c release TextMetricsBenchmark` runs 20 repetitions per generated 1 KiB, 1 MiB, 10 MiB and 100 MiB fixture, including mixed Unicode/CRLF and an unbroken line. It reports median/p95 index construction and batches of caret/selection/line queries. This is an informational microbenchmark; it does not measure app startup, typing latency, native Find, RSS or energy, and does not close M5 performance gates.

`swift run -c release RecoveryBenchmark` measures recovery-store restoration, selection-only checkpoints and one-tab edits with 20 open tabs totaling 5 MiB, then 100 open plus 20 recently closed tabs totaling 30 MiB. Each tab starts at 256 KiB; alternating ASCII and Arabic/combining-mark/emoji fixtures preserve CRLF. Each operation has 20 samples, an arithmetic middle-pair median and nearest-rank p95 (sample 19 of 20). JSON includes raw samples, software/hardware basics, and bytes read/written plus atomic-write counts at the recovery I/O boundary. Report schema 2 additionally counts fingerprint lookups, directory listings and removals; these new counters do not change the workloads, timing boundaries or verification used by the schema-5 baseline. These counters are logical API traffic, not physical device I/O. Recovery verification compares canonical encoded bytes outside timing. Each restoration creates a new store against warm filesystem caches; this is not cold launch or first editable frame. Run without a debugger and after CI/other tests finish, record machine/power/cache conditions and commit, and retain the JSON under `docs/validation/`. Generated fixtures use a new private temporary root and are removed afterward; no app or normal recovery directory is opened. Wall-time results are informational on this shared Mac and have no CI speed threshold. Startup, typing, memory, energy, minimum hardware and Instruments evidence remain separate #12 gates.

## Optimized app performance suite

Performance-driver exit regressions execute the real launch/interaction/profile shell scripts with fake native tools and generated temporary files. The [retention fix](docs/validation/2026-09-08-performance-retention.md) preserves original fixtures and exit status after test/verification/extraction/profile failures and interrupted statuses, cleans exactly once after complete success, and fails if that cleanup fails. This offline coverage never launches a NoteHush app or certifies native input/performance.

Issue #35 adds the separate `NoteHushPerformance` scheme and `bash scripts/test_performance.sh`; follow [the protocol](docs/PERFORMANCE.md). The [initial M4 Pro baseline](docs/validation/2026-09-07-app-launch-baseline.md) passed all three workloads and complete recovered-buffer verification; PRD budgets and minimum hardware remain unverified. Its app uses a distinct bundle ID, mandatory UUID workspace and exact product sandbox entitlements. Resolved optimization/isolation flags and scheme actions are checked before launch. Sample extraction requires the documented first-frame/readiness identifiers and seconds units, and rejects missing/extra intervals, scenarios, retries, nonfinite values and fewer than 20 samples; every slow observation is preserved. This opt-in suite must run after functional CI and exclusive-input preparation. Its longer per-case duration allowance accommodates 20 launches without changing functional CI timeouts.

Normal CI compiles and verifies the optimized target with `scripts/build_performance.sh` without launching it.
